API documentation

Every operation is an HTTP request to /v1/<operation> on this server. You can try each one from your browser with the API tester.

On this page: Basics · Operations · Errors · Rate limits

Basics

  • Method. Every key/value operation is a POST request. Only health uses GET. There is no way to download a value by following a link.
  • Request body. A JSON object, except for putraw, whose body is the value itself and whose other fields are URL parameters. Browsers should send Content-Type: text/plain;charset=UTF-8, which avoids a CORS preflight request; the server reads the body as JSON whatever its declared type. Members not listed for an operation are ignored. Nested objects, arrays, and duplicate members are rejected.
  • Response body. A JSON object with "ok": true on success, or "ok": false and an "error" code on failure. The exception is a successful getraw, whose body is the value itself.
  • Keys. Exactly 32 characters from the base32 alphabet (a–z and 2–7), not case-sensitive. Generate keys randomly (32 random base32 characters is 160 bits), because anyone who guesses a key has full control of its value. {{keyFormatNote}}
  • Buckets. Named storage areas with their own limits, created by the operator. Names are 1–32 characters from the same base32 alphabet, not case-sensitive. When a request does not name a bucket, the default bucket ({{defaultBucket}}) is used. The buckets operation lists them.
  • Values. Any bytes, up to the bucket's maximum item size ({{defaultMaxItemSize}} in the default bucket). put and get carry values as base64 text inside JSON. putraw and getraw carry the raw bytes as the request or response body, which is 25% smaller on the wire and needs no encoding. Both kinds of operation work on the same stored items.
  • Times. expires is a Unix timestamp (seconds since 1970-01-01 UTC). ttl (time to live) is a duration in seconds.
  • Lifetime. Every item is deleted when it expires. Reading an item never extends its lifetime. Storing a key again replaces both its value and its expiration time.
  • Cross-origin requests. Web pages on any site may call the API. CORS allows every origin, without credentials. Every operation can be called without a CORS preflight request.
  • Encryption. The server stores exactly what it receives. Encrypt values before storing them. The reference JavaScript client derives both the key and an AES-256-GCM encryption key from a single word phrase.

POST /v1/put Try it

Stores a value under a key, replacing any value already stored under that key in that bucket.

Request body (JSON)

FieldTypeDescription
keystringrequiredThe key.
valuestringrequiredThe value, base64-encoded. The standard (+/) and URL-safe (-_) alphabets are both accepted, with or without = padding, and whitespace is ignored. An empty string stores a zero-length value.
bucketstringoptionalBucket name. Omitted, null, or "" means the default bucket.
ttlnumberoptionalRequested lifetime in seconds. Omitted or null means the bucket's default ({{defaultTtl}} in the default bucket). The value is clamped to the range from 60 seconds to the bucket's maximum ({{defaultMaxTtl}} in the default bucket).

Response

FieldTypeDescription
okbooleantrue
expiresnumberWhen the item will be deleted (Unix time).
ttlnumberThe lifetime that was applied, in whole seconds, after clamping.
sizenumberSize of the stored value in bytes, after base64 decoding.
POST /v1/put
{"key": "k5rqgl3wbv2nqv7zm4hy6i3yaq6ln2zk", "value": "SGVsbG8=", "ttl": 600}

200 OK
{"ok": true, "expires": 1790000600, "ttl": 600, "size": 5}

Errors: bad_request (key or value is missing, value is not a string, or ttl is not a number), invalid_key, invalid_bucket, invalid_value, unknown_bucket, too_large, rate_limited, bucket_disabled, storage_full.

POST /v1/putraw Try it

Stores a value like put, but the request body is the value itself, so it needs no encoding. The other fields are URL parameters.

URL parameters

ParameterDescription
keyrequiredThe key.
bucketoptionalBucket name. Absent or empty means the default bucket.
ttloptionalRequested lifetime in seconds, as a decimal number. It is interpreted and clamped the same way as put's ttl.

Request body

The value's bytes, exactly as they should be stored. An empty body stores a zero-length value. The request must have a Content-Length header or use chunked transfer encoding, as HTTP clients do automatically.

The Content-Type header is ignored. From a browser, send no Content-Type (the default for a Uint8Array or ArrayBuffer body, and for a Blob with no type) or text/plain. Any other type, such as application/octet-stream or a file's own type, makes the browser send a CORS preflight request first. That still works, but it is slower.

Response

The same JSON as put: ok, expires, ttl, and size.

POST /v1/putraw?key=k5rqgl3wbv2nqv7zm4hy6i3yaq6ln2zk&ttl=600

Hello

200 OK
{"ok": true, "expires": 1790000600, "ttl": 600, "size": 5}

Errors: bad_request (key is missing, ttl is not a number, or the upload ended early), invalid_key, invalid_bucket, unknown_bucket, too_large, rate_limited, bucket_disabled, storage_full.

POST /v1/get Try it

Reads a value.

Request body (JSON)

FieldTypeDescription
keystringrequiredThe key.
bucketstringoptionalBucket name. Omitted, null, or "" means the default bucket.

Response

FieldTypeDescription
okbooleantrue
valuestringThe value, base64-encoded with the standard alphabet and = padding.
expiresnumberWhen the item will be deleted (Unix time).
sizenumberSize of the value in bytes.
POST /v1/get
{"key": "k5rqgl3wbv2nqv7zm4hy6i3yaq6ln2zk"}

POST /v1/getraw Try it

Reads a value like get, but the response body is the value itself.

Request body (JSON)

The same as get: key (required) and bucket (optional).

Response

On success, the status is 200 and the body is the value's bytes, with these headers:

HeaderDescription
Content-TypeAlways application/octet-stream.
KV-ExpiresWhen the item will be deleted (Unix time).
KV-SizeSize of the value in bytes (the same as Content-Length).

On failure, the response is the usual JSON error with a status other than 200. Check the status before treating the body as the value.

POST /v1/getraw
{"key": "k5rqgl3wbv2nqv7zm4hy6i3yaq6ln2zk"}

200 OK
Content-Type: application/octet-stream
KV-Expires: 1790000600
KV-Size: 5

Hello

Errors: the same as get.

POST /v1/info Try it

Reports whether a value exists, and its size and expiration time, without downloading it. This lets a device wait for another device's upload cheaply.

Request body (JSON)

The same as get: key (required) and bucket (optional).

Response

FieldTypeDescription
okbooleantrue
existsbooleantrue if a value is stored under this key in this bucket and has not expired. A missing value is not an error.
expiresnumberWhen the item will be deleted (Unix time). Only present if exists is true.
sizenumberSize of the value in bytes. Only present if exists is true.

Errors: bad_request (key is missing), invalid_key, invalid_bucket, unknown_bucket, rate_limited, bucket_disabled.

POST /v1/del Try it

Deletes a value immediately.

Request body (JSON)

The same as get: key (required) and bucket (optional).

Response

FieldTypeDescription
okbooleantrue
deletedbooleantrue if a value was deleted. false if there was nothing to delete: the key was never used in this bucket, or its value was already deleted or has expired.

Errors: bad_request (key is missing), invalid_key, invalid_bucket, unknown_bucket, rate_limited, bucket_disabled.

POST /v1/buckets Try it

Lists the buckets that are currently enabled, and their limits.

Request body (JSON)

{}, or an empty body. There are no fields.

Response

FieldTypeDescription
okbooleantrue
defaultBucketstringName of the bucket used when a request does not name one.
bucketsarrayOne object per bucket, with these fields:
name (string): the bucket's name.
maxItemSizeBytes (number): the largest value the bucket accepts, in bytes.
defaultTtl (number): the lifetime used when a request does not ask for one, in seconds.
maxTtl (number): the longest lifetime the bucket allows, in seconds.

POST /v1/phrase Try it

Returns random words from the EFF short wordlist #1, for use as a secret that is easy to type. Nothing is recorded. Generating phrases on your own device is preferred.

Request body (JSON)

FieldTypeDescription
wordsnumberoptionalNumber of words: a whole number from 5 to 10. Omitted or null means 6. Six words (about 62 bits) is the recommended minimum.

Response

FieldTypeDescription
okbooleantrue
phrasestringLower-case words separated by hyphens, e.g. crop-visor-quilt-nomad-brave-flint. One word in the list, yo-yo, contains a hyphen itself.

Errors: bad_request (words is not a whole number from 5 to 10).

Errors

A failed request has an HTTP error status and a body like {"ok": false, "error": "not_found"}.

HTTPerrorMeaning

400invalid_keyThe key is not in a valid format.
400invalid_bucketThe bucket name is not in a valid format.
400invalid_valueThe value is not valid base64 (put only).
404not_foundNothing is stored under this key in this bucket, or it has expired.
404unknown_bucketThere is no bucket with this name.
404unknown_endpointThere is no operation with this name.
405method_not_allowedWrong HTTP method. Use POST, or GET for health.

500internal_errorAn unexpected server error. The response also has a correlationId.

Rate limits

Requests are limited per client network: one IPv4 address, or one IPv6 /64 prefix. Each limit allows a burst, then refills gradually. A request over a limit is answered with 429 rate_limited.

Writesput, putraw, del{{writeLimit}}
Readsget, getraw, info{{readLimit}}
